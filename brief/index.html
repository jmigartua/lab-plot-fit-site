The brief

The brief

The founding request of 17 October 2026, organised into numbered requirements, then kept verbatim below. Ids never change; requirements added later are appended with the log entry that adds them.

What the app is

  • R01 A native macOS application built with Tauri, as the previous apps of the family are (diff-ref-struct, difes-shell), with the features of KaleidaGraph: what it does and how it works, studied first from the running demo and its manual.
    Working name of the brief: lab-plot-fit; the name is open (L005).
  • R02 The interface of the TRAE IDE (the VS Code family): the same window as this editor has — activity bar, sidebar, tabs in a main area that splits, bottom panel, inspector, command palette — but holding KaleidaGraph's features instead of code.
  • R03 Very easy to use, and for that simplicity a plethora of options: KaleidaGraph's balance, kept. The common path is short; every option is there when it is wanted.

Who it is for

  • R04 The tool of the students in the laboratory practices of the Physics degree: Técnicas Experimentales I, II, III and IV (UPV/EHU): the data of each practice entered, plotted, fitted and reported with it.

The live mode

  • R05 A work mode like performing an experiment connected to an instrument, where the instrument is the student at the bench, reading the apparatus and typing the numbers in. As soon as a datum enters, the app does what it has been programmed to do: the plots are created and stay synced with the data, and the fits, where there are fits, are redone at once. A work mode of its own.

Beyond the list

  • R06 These are the features the brief could name; be wise, propose, innovate, design.

How the work is done

  • R07 Work the same way as the previous projects, diff-ref-struct (the Rietveld app) and inverse-problems-configuration-space: one repository with the core, the app and the ecosystem; every session logged; the app's standing conventions carried over.
  • R08 The website associated with the project, built as theirs are: the log, the ideas (the seed-place, each idea with its own log), the brief, the background, the design, the roadmap, the release notes and the manuals, in the family kit.
  • R09 Study KaleidaGraph first: its features and how it works, from the running demo (reached from the session) and the manual, before any code; the inventory on the site, each claim with its source.

The app as a fork of the TRAE IDE, the practices, the languages (added 17 October 2026, L009–L011)

  • R10 The app is coded as if it were a fork of the TRAE IDE, not on diff-ref-struct's app: its notes and learnings are taken, its code is not. The sense is that the app is as the TRAE IDE is. Read as a fork of Code – OSS, the open source of VS Code that TRAE itself is built on (L009); R01's Tauri is amended accordingly.
    Josu, 17 October 2026: "instead of reusing, I would prefer to take all the notes in that case, the learnings, but code it as if it were a fork of the TRAE IDE, the sense is that I would like it to be as the TRAE IDE is."
  • R11 The practices are those Josu guides for the UNED students, Técnicas Experimentales I first (eight practices, in practices/uned/tecI/), since the practices of the four courses are practically the same; the other courses follow.
  • R12 English and Spanish for now; Basque later (design question Q4, decided in L010).

The ideas given the green light for version 1 (added 17 October 2026, L014)

  • R13 Practice templates (from I02): a practice as a file the teacher prepares once, with the columns, their units and uncertainties, the plots, the fits, the derived quantities and the questions; the student opens it and the Bench is ready. The student's project stays editable; what the template wired is marked as the teacher's and cannot be deleted by accident; the template decides whether expected values are shown at the Bench (L013).
  • R14 A unit and an uncertainty on every column (from I03): the instrument's resolution, a typed value, a column of its own, or none; propagated through formulas (quadrature, or the course's upper bound) and into weighted fits; axes labelled from the columns; a sum of metres and seconds refused.
  • R15 The visible pipeline (from I04): everything in a project is a node that depends on others, recomputed along the graph when something changes, which is what makes the Bench live; the graph shown as a small diagram of what feeds what.
  • R16 The lab report exported (from I05): figures by the family's rules (every character typeset by LaTeX, identical geometry across a series), the fits' parameters with uncertainties as tables, the data as CSV, a report skeleton with the template's questions as headings; everything regenerated from the project.

A general tool (added 17 October 2026, L015)

  • R17 The app is not tied to those practices. It is free to use in its complete extension with whatever other practices, or with no practice at all: to enter or import data, make a figure and print it, for instance. The practices and their templates are one use of a general data, plot and fit tool with KaleidaGraph's features; every feature works on a blank project.
    Josu, 17 October 2026: "I hope the app will not be tied only to those practices… it will be free to use in its complete extension with whatever other practices, or even just to input and/or import data for making a figure and printing, for instance."

Measurement uncertainty by the GUM (added 17 October 2026, L022)

  • R18 Monte Carlo propagation and GUM compliance: uncertainties evaluated and expressed as the GUM (JCGM 100:2008) does, Type A and Type B standard uncertainties, the law of propagation with an uncertainty budget, effective degrees of freedom, the coverage factor and the expanded uncertainty; and the propagation of distributions by Monte Carlo as Supplement 1 (JCGM 101:2008) does, with coverage intervals and the validation of the GUM framework against it. The course's error rules are mapped onto the GUM's terms, so that a student's report can be written either way.
    Josu, 17 October 2026: "could you add a Monte Carlo, GUM compliance".

Files in and out (added 17 October 2026, L024)

  • R19 A file dragged to the Dock icon opens in the app: if the app is already open, the file opens in it; if not, the app opens with the file. A data file, or a graph file, if the app has graph files as KaleidaGraph does (it will: the project's plot files).
    Josu, 17 October 2026. Already in APP_CONVENTIONS §7 for diff-ref-struct; now a requirement of this app, with the plot file named.
  • R20 The decimal separator is the point, not the comma: in what the app shows, in what it writes, and in its files, whatever the Mac's locale. A comma typed on entry is accepted and shown as a point. This amends APP_CONVENTIONS §10, which showed numbers with the system's separator.
    Josu, 17 October 2026: "yes, I want the decimal points as points, not commas", after the demo read a point-decimal file as integers under the Spanish locale (L023).
  • R21 A smart importer: it guesses how the data are organised in a file (the delimiter, the decimal separator, comment and preamble lines, the header and the units in it or in a row of their own, columns of numbers or text, data laid out in rows instead of columns), says what it guessed and lets the user correct it, and saves a copy of the file in one of the app's standard data formats.
    Josu, 17 October 2026. The app's standard data formats: CSV with a name(unit) header and point decimals (the core's since 0.1.0), and the project file (JSON, since 0.4.0).

On this page

    What this is

    The working site of one project: to build a Mac app with the features of KaleidaGraph and the window of the TRAE IDE, for the laboratory practices of the Physics degree, with a live bench mode where the student's readings become plots and fits as they are typed. It holds the brief, the study of KaleidaGraph, the design, the seed-place of ideas, a dated log of every step, the release notes and the manuals of the core and the app.
