L0202026-10-17work

Core 0.4.0: the project and its dependency graph, the mechanism under the Bench (R15)

A project holds tables, formulas on them, fits (a line, a polynomial, a model) on two columns, and derived quantities as expressions over the fits' parameters with their errors propagated; every one is a node, the edges are read from the expressions, and a change to a cell recomputes what depends on it in topological order, once, returning the list of what changed with each node's outcome. That list is what the Bench will draw on each reading (I01, R05); the graph is what I04 asked to show. The project is a JSON file that keeps its results, so that the app opens it without recomputing and the command line can run it, change cells and save it. Checked on Ley de Hooke as a whole project: both series, T = t20/20 and T\(^{2}\) with their uncertainties, the static and the dynamic line fits, K by the guide's upper bound, αm by quadrature, the spring's mass; one chronometer reading corrected recomputes T, T\(^{2}\), the dynamic fit and its three derived quantities, nothing of the static series, and the incremental result equals a fresh run to the bit; a reading added past the table's end extends every column and a row without its mass is not a point of the fit; a formula that fails (the logarithm of a voltage with its unit) reports its message and the rest of the project runs. Two things learned: a topological order is not unique, so a test must check the dependencies, not a sequence; and a weighted fit's \(\sigma\) can be taken from the y column's own uncertainties ("auto"), which is how the guides' instrument resolutions reach the fit without a column of their own.

L0182026-10-17work

Core 0.3.0: formulas on columns with units and propagated uncertainties (R14)

What every practice's derived columns need, in the core: a formula name[unit] = expr over the table's columns (by name or by KaleidaGraph's cN), evaluated row by row in SI, its unit derived from the columns' units by the rules (a sum needs equal dimensions, a quantity's exponent must be a plain number, a function wants no unit, sqrt halves the dimensions) and written in the unit asked for in brackets, or in the SI base form of its dimension; the uncertainty of each cell propagated from the columns' rules by quadrature or by the upper bound, with numerical partial derivatives, and kept with the new column. Repeats in a row are mean(t1, …, t5) and sem(…), the latter the course's "error cuadrático". The constant g0 carries its unit. Checked on Hooke's series as the guide asks: M in grams to kilograms by a unit change; T = t20/20 with the chronometer's resolution propagated; T\(^{2}\) in \(\mathrm{s}^{2}\) with ΔT\(^{2}\) = 2T·ΔT; P = M·g0 in newtons with the unit derived as kg·m/\(\mathrm{s}^{2}\); \(\Delta\)(b/a) against the guide's closed form; the refusals (the wrong unit asked for, seconds plus kilograms, T^T, exp of a time). One lesson from the real file: a header written by hand ("s_2" for \(\mathrm{s}^{2}\)) must not stop a formula that does not touch its column, so a column's unit is parsed only when it is used. Not yet: aggregates over a whole column inside a formula (they are lpf stats for now), and the dependency graph (R15) that will recompute these columns when a cell changes, which is the next step.

L0172026-10-17work

Core 0.2.0: the general curve fit and the polynomial fit, the engine's method lifted, not its code

diff-ref-struct's least-squares engine (lsq.rs, 2318 lines) is welded to its Rietveld types (the pattern, the model, the parameter set with its dual-number Jacobian), so lifting it as code was not practical. Its method was lifted instead, written in 300 lines for y = f(x; p) with a few parameters and a few hundred points:

  • the normal matrix A = JᵀWJ scaled to unit diagonal and decomposed into its eigenvectors by Jacobi rotations; directions with λ < \(10^{-12}\) λ_max are singular and named by the parameters that carry them;
  • Gauss–Newton steps, with Marquardt damping λ = \(10^{-3}\) and \(\times 10\) only when a step would raise \(\chi^2\), ÷10 on each accepted step; bounds that hold a parameter at its limit while the gradient pushes it out (SciPy's trf lands on the same point: \(\tau\) = 10 with V₀ at its conditional optimum, test fits);
  • the Jacobian by central differences, since the equation is the user's text;
  • errors \(\sigma\)_j = √((A\(^{-1}\))_jj \(\chi^2\)/dof) from the scatter, or √((A\(^{-1}\))_jj) from the weights, or scaled, the convention named in the result as for the line (L016). The equations are compiled once by a grammar of the core's own (expr): unary minus binds below ^ as in mathematics (−x\(^{2}\) = −(x\(^{2}\))), ^ is right-associative, and KaleidaGraph's definitions compile as written (I10). The polynomial fit (to order 9, as KaleidaGraph's) uses the same solve on a centred, scaled design matrix. Checked: a synthetic capacitor discharge against curve_fit to 1e-7 on the parameters and 1e-5 on the errors in three conventions and bounded; Hooke's series as a nonlinear fit equal to the closed-form line to 1e-9; a polynomial against NumPy's lstsq with an explicit covariance to 1e-9. The command line: --model, --start, --bounds, --poly, eval. The reference script records a convention worth knowing: curve_fit scales its covariance by \(\chi^2\)/dof even when \(\sigma\) is given (absolute_sigma=False), which is this core's "weights scaled"; KaleidaGraph's convention for its parameter errors is still to be read off the demo.

Phase 1 opens: the Rust core, Hooke's two fits against SciPy

The crate lpf in core/, a library and the lpf command line (JSON out), with its first slice:

L0022026-10-17finding

The running demo reached: the Accessibility tree, not Interceptor

How the session reads and drives KaleidaGraph 5.0.6 on Josu's Mac, which is an Intel machine:

  • the Interceptor macOS bridge, the family's tool for native apps, is an arm64-only binary and fails there with "Bad CPU type in executable"; its LaunchAgent sat in a spawn loop. Not usable;
  • Apple Events (osascript, System Events) are refused for the host process (TRAE), and KaleidaGraph has no scripting dictionary of its own anyway;
