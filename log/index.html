The Fits module: a fit is a file, one report whatever the model, its curve and residuals on the plot; Search, Source Control and Extensions back

The third module (app 0.6.0, core 0.10.0). A fit is a file of the project, name.fit.json: its table, x and y, the kind (line, poly, model, or KaleidaGraph's exponential, logarithmic, power), and how (through the origin, the weights as a column or a value, scaled, the order, the model with its starting values and bounds, linearised or nonlinear, the confidence level). lpf fit run runs it and reports the same shape whatever the model: the equation with the columns' names (P = m·delta_x + n), each parameter with its error, its unit from the columns' units (N/m, N; c2 in N/m^2; m1 of an exponential in 1/s) and written by the course's rule (m = 16.2 \(\pm\) 0.2 N/m; n = −0.019 \(\pm\) 0.015 N keeps two figures because the error starts with 1), the points and degrees of freedom, \(\chi^2\), \(\chi^2\)/ν, R\(^{2}\) and r, where the errors come from, whether it converged, KaleidaGraph's note on the presets, the Linear fit's statistics, the residuals row by row, the curve, the report's lines, and the matching lpf fit result in full. A plot that lists the fit in its fits draws the curve over its view (sampled by the core as fractions) and the residuals in a panel of their own below, on an axis symmetric about zero with the x axis shared. One lesson: renaming the equation's x to the column's name must go by identifier, or exp becomes etp. In the window: the fit editor shows the report with the controls that edit the file (kind, origin, order, model and start, weights, scaled, method, confidence), refit when the file or its table changes, Copy the report (⌘C); "New fit…" on a plot asks the kind and the weights, writes the fit beside the table, adds it to the plot (the curve and residuals appear) and opens the report beside; on a table it asks x and y too. The plot's toolbar shows its fits as chips (× removes one from the plot, the file stays) and "+ fit". Checked in the window on Hooke's static series: the line and its label over the data, the residual panel (app/fits-module-plot-2026-10-17.png), the report (app/fits-module-report-2026-10-17.png). Josu, the same afternoon, on the stripping: keep the activity bar's buttons, extensions and git/GitHub are options he wants open for later. Nothing had been removed, only hidden by product.json's list and two defaults, so the product now hides only Run and Debug; Search, Source Control and Extensions are back, git.enabled is true (autofetch off), and extensionsGallery points to Open VSX, the registry Code – OSS forks use. The chat, the onboarding, telemetry and updates stay off.

The Plots module: a plot is a file that follows its table, resolved by the core into fractions, drawn by the window

The second module (app 0.5.0, core 0.9.0). A plot is a file of the project, name.plot.json, naming its table (relative to itself), the x column, the y columns with their error-bar columns, the kind, the title, log axes, fixed ranges; it holds no copy of the data. The core resolves it (lpf plot): the points with their values and their fractions of the axes, the error bars' ends as fractions, and the axes with their ticks placed for the plot area's size in pixels. The window maps fractions to pixels and nothing else; the values under the cursor come from the axis's own map (a + b·t, or 10^(a + b·t)), which the core sends. So the ticks are the core's and tested: 1-2-5 steps, as many as the space allows (one label per 70 px along x, 32 along y), the range anchored on ticks, the common factor (×\(10^{-5}\)) or the offset (+ 10.6048) taken into the axis title when the digits that change are far down (diff-ref-struct's L119, where 0.00002596, 0.00002598 … overlapped), the true minus, log axes by decades. Fractions come from the tick's index, exact, after a floating-point lesson (10.6048 / 0.0001 was 106047.999). In the window: "New plot from this table" on a table's title asks x, the y columns and the error-bar column and writes the plot file beside the table (lpf plot new), opening it beside; the plot's controls (x, y, error bars, kind, log x, log y, title) edit the file, so ⌘Z applies; a box dragged zooms, the wheel zooms at the cursor, ⌥-drag pans, double-click resets, with the ranges sent to the core as the view; export as SVG or PNG (2×), copy as SVG. A plot always follows its data: the table's file is watched and the plot redrawn, and a table open in the Data module reaches the plot through auto-save. Checked in the window on Hooke's static series: the plot with error bars from delta_x (app/plots-module-2026-10-17.png), a zoom box with the axes re-ticked and the readout (app/plots-module-zoomed-2026-10-17.png), the reset, and row 0 moved on the plot the moment the CSV was changed on disk. tools/clickat gained drag for the box.

L0252026-10-17work

Core 0.7.0: the smart importer (R21)

A text data file of unknown layout is read with its layout guessed and reported, so that the app can show the guess with the first rows and let the user correct it before accepting (APP_CONVENTIONS §7, Import):

  • the delimiter is the one among tab, semicolon, comma and whitespace that splits the most lines into the same number of fields; the decimal separator is read from the fields that look like numbers under each convention (a comma delimiter forces the point); comment lines, blank lines and a preamble (an instrument's banner) are skipped and listed with their line numbers; the header is the first non-numeric line of the data block, its units read from name(unit) or name [unit] or from a second line of units; a column is numbers, text (left empty and noted) or nothing; data laid out one variable per row, a label first, are transposed; a file that is not UTF-8 is read as Latin-1;
  • the user's corrections (Overrides): the delimiter, the decimal separator, the header line or none, the transposition; a line that is not a data line is refused by its number;
  • the copy in the app's standard format: CSV with name(unit) headers, commas between fields and the point as the decimal separator (R20), which reads back as the same table. Checked on the practices' own files, a KaleidaGraph text export, a Spanish file with semicolons and decimal commas, an oscilloscope-like export with a banner and a units row, whitespace with no header, transposed data. The decimal point everywhere (R20) is now the core's rule in three places: the writer always writes a point, the reader and the importer accept a comma and say so, and the formulas' output is written with a point.

L0232026-10-17finding

KaleidaGraph's fit1 on the Hooke data, read off the demo: every printed digit equals the core's, and its errors are the scatter convention

The gate of phase 1 (I11): the Hooke static series was fed to the running demo and fitted with Curve Fit ▸ General ▸ fit1 (y = m1 + m2·M0, the fit the course's regression guide tells the students to use), with Display Equation on. KaleidaGraph printed m1 = −1,91 \(\pm\) 1,5252, m2 = 1,617 \(\pm\) 0,022861, Chisq = 148,96, R = 0,9984 (the table is kept as manuals/kaleidagraph/fit1_hooke_static_2026-10-17.png). The core on the same numbers: n = −1.910023 \(\pm\) 1.525186, m = 1.616979 \(\pm\) 0.022861, \(\chi^2\) = 148.962, r = 0.998405: every digit KaleidaGraph printed, which is now the test kaleidagraph. So KaleidaGraph's "Error" of the General fit is the scatter convention, \(\sigma\)_j = √((A\(^{-1}\))_jj \(\chi^2\)/ν), the same as SciPy's linregress and the core's default; the theory manual's "to be confirmed" is confirmed. Two things learned on the way:

  • the demo read the tab-delimited file with the Mac's Spanish locale: "0.005" became 5 and "0.10" became 10 (a decimal point is dropped; a decimal comma is read). The series it fitted is therefore x' = 1000·Δx, y' = 100·P, which scales m and n and their errors and leaves R alone; the core fitted the same scaled numbers. The app must accept both separators on entry (I08, APP_CONVENTIONS §4 "Data") and say which it took;
  • driving the demo from a session: the file goes in through Launch Services (open -a), which skips the Open panel whose column view ignores Accessibility selection; the dialogs' buttons (Text File Input Format: OK; Curve Fit Selections: Select All, OK) answer to Accessibility presses; the Variable Selection dialog's X and Y cells do not, and KaleidaGraph rebuilds its menu bar (Curve Fit, Object) only when it is the active app, so it was activated for a second and Trae reactivated, after which the fit menus answered in the background. Core 0.4.0: the project and its dependency graph, the mechanism under the Bench (R15)

A project holds tables, formulas on them, fits (a line, a polynomial, a model) on two columns, and derived quantities as expressions over the fits' parameters with their errors propagated; every one is a node, the edges are read from the expressions, and a change to a cell recomputes what depends on it in topological order, once, returning the list of what changed with each node's outcome. That list is what the Bench will draw on each reading (I01, R05); the graph is what I04 asked to show. The project is a JSON file that keeps its results, so that the app opens it without recomputing and the command line can run it, change cells and save it. Checked on Ley de Hooke as a whole project: both series, T = t20/20 and T\(^{2}\) with their uncertainties, the static and the dynamic line fits, K by the guide's upper bound, αm by quadrature, the spring's mass; one chronometer reading corrected recomputes T, T\(^{2}\), the dynamic fit and its three derived quantities, nothing of the static series, and the incremental result equals a fresh run to the bit; a reading added past the table's end extends every column and a row without its mass is not a point of the fit; a formula that fails (the logarithm of a voltage with its unit) reports its message and the rest of the project runs. Two things learned: a topological order is not unique, so a test must check the dependencies, not a sequence; and a weighted fit's \(\sigma\) can be taken from the y column's own uncertainties ("auto"), which is how the guides' instrument resolutions reach the fit without a column of their own.

Core 0.2.0: the general curve fit and the polynomial fit, the engine's method lifted, not its code

diff-ref-struct's least-squares engine (lsq.rs, 2318 lines) is welded to its Rietveld types (the pattern, the model, the parameter set with its dual-number Jacobian), so lifting it as code was not practical. Its method was lifted instead, written in 300 lines for y = f(x; p) with a few parameters and a few hundred points:

  • the normal matrix A = JᵀWJ scaled to unit diagonal and decomposed into its eigenvectors by Jacobi rotations; directions with λ < \(10^{-12}\) λ_max are singular and named by the parameters that carry them;
  • Gauss–Newton steps, with Marquardt damping λ = \(10^{-3}\) and \(\times 10\) only when a step would raise \(\chi^2\), ÷10 on each accepted step; bounds that hold a parameter at its limit while the gradient pushes it out (SciPy's trf lands on the same point: \(\tau\) = 10 with V₀ at its conditional optimum, test fits);
  • the Jacobian by central differences, since the equation is the user's text;
  • errors \(\sigma\)_j = √((A\(^{-1}\))_jj \(\chi^2\)/dof) from the scatter, or √((A\(^{-1}\))_jj) from the weights, or scaled, the convention named in the result as for the line (L016). The equations are compiled once by a grammar of the core's own (expr): unary minus binds below ^ as in mathematics (−x\(^{2}\) = −(x\(^{2}\))), ^ is right-associative, and KaleidaGraph's definitions compile as written (I10). The polynomial fit (to order 9, as KaleidaGraph's) uses the same solve on a centred, scaled design matrix. Checked: a synthetic capacitor discharge against curve_fit to 1e-7 on the parameters and 1e-5 on the errors in three conventions and bounded; Hooke's series as a nonlinear fit equal to the closed-form line to 1e-9; a polynomial against NumPy's lstsq with an explicit covariance to 1e-9. The running demo reached: the Accessibility tree, not Interceptor

How the session reads and drives KaleidaGraph 5.0.6 on Josu's Mac, which is an Intel machine:

  • the Interceptor macOS bridge, the family's tool for native apps, is an arm64-only binary and fails there with "Bad CPU type in executable"; its LaunchAgent sat in a spawn loop. Not usable;
  • Apple Events (osascript, System Events) are refused for the host process (TRAE), and KaleidaGraph has no scripting dictionary of its own anyway;
  • the Accessibility API is trusted for the process, and Screen Recording was granted during the session. A small Swift tool (AXUIElement on the program's pid) dumps the windows, the menu bar with every item and submenu, the Formula Entry window's controls, and presses menu items; screencapture -l <window id> captures a window by its id even on another Space. Checked: Windows ▸ History pressed through the tree opened the History window; the Data 1 and Formula Entry windows captured as images. The menu inventory of L004 was read this way.
