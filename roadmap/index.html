Roadmap

Phases

Study, then the core, then the app around it, then the Bench, then the report and the class. Each phase ends with a named artefact and a log entry. Only phase 0 is detailed; the later phases are drawn from its feature set and their detail is written when phase 0 closes.

PHASE 0 · open

The repository, the study of KaleidaGraph, the practices, the proposal

Know what KaleidaGraph does, and what the practices of Técnicas Experimentales need, before deciding what this app will do.

  • Private repository, site skeleton, brief organised into requirements, working method in CLAUDE.md, the app's conventions and workflows carried over. done (L008)
  • The running demo reached from the session, through its Accessibility tree. done (L002)
  • The KaleidaGraph inventory from the running program and the manual's contents: one entry per capability, with sources. first pass (L004); the pages of the curve-fit chapter, the export formats and the demo's limits still to be read, then the inventory closed.
  • The practices of Técnicas Experimentales I read from Josu's UNED guides: for each, what is measured, with what instrument and uncertainty, the tables, what is plotted, what is fitted and what it gives, what the Bench shows: the eight, with the course's error rules and its KaleidaGraph regression guide. done (L011) The first practice (Q6): Ley de Hooke proposed, for Josu. Técnicas Experimentales II–IV follow (R11).
  • The app decided as a fork of Code – OSS, as the TRAE IDE is (R10); the languages English and Spanish (R12). decided (L009, L010)
  • Q1–Q6 decided by Josu: Rust over stdio, the name kept, text files only, templates editable, Hooke first; I02–I05 given the green light as R13–R16. decided (L013, L014)
  • "Most used" measured for the teaching laboratories (syllabi, licences, live acquisition), two more programs read in full, the gaps against KaleidaGraph listed. to do
  • The design proposal: the window, the modules, the Bench, the data model, six questions. draft (L006); the feature set of version 1 as a table (P01…) drawn from the inventory, the gaps and the practices, for Josu to decide.
  • The seed-place seeded with twelve ideas, the Live Bench assessed. done (L007)
Done when the KaleidaGraph inventory is closed and the version-1 feature table is on the site. Met already: the first practice's data in the repository, Q1–Q6 decided (L010, L013). Phase 1 opens in parallel (L015).
PHASE 1 · closed (L023)

The core: tables, units, formulas, fits

Everything of version 1 that computes, in the core and on the command line, each feature tested against an independent source: SciPy for the fits, KaleidaGraph's own results on its example files, hand calculations for units and propagation. In Rust, the command line as the app's interface (L013).

  • The table: columns with name, unit, uncertainty rule; CSV with a header of units read and written; KaleidaGraph's c0, c1 … as addresses. done (L016, core 0.1.0); types and formats, KaleidaGraph's text exports: to do.
  • Repeated readings by the course's rule and the propagation of errors by quadrature and by the upper bound, with each error's contribution. done (L016, core 0.1.0)
  • Formulas on named columns with units checked and uncertainties propagated, repeats in a row by mean and sem, the unit asked for in brackets done (L018, core 0.3.0; test formulas); KaleidaGraph's library files read as definitions: to do.
  • The fits: linear (with and without weights, through the origin) done (L016, core 0.1.0; test hooke against SciPy); the general nonlinear fit of any equation with bounds, and polynomials to order 9, with parameters, errors in three conventions, covariance, \(\chi^2\)/ν, R\(^{2}\), residuals done (L017, core 0.2.0; test fits against SciPy and NumPy); KaleidaGraph's Exponential, Logarithmic and Power fits both ways, the Linear fit's statistics and the confidence bands done (L021, core 0.5.0; test presets); the comparison with KaleidaGraph's fit1 on the demo (I11) done (L023; test kaleidagraph, every printed digit).
  • The smart importer (R21): a file's layout guessed and reported, the user's corrections, a copy in the app's standard format with the point as the decimal separator (R20) done (L025, core 0.7.0; test import); Excel files, fixed width, dates: later.
  • Measurement uncertainty by the GUM and Monte Carlo by its Supplement 1 (R18): the budget, ν_eff, k, U; M trials with coverage intervals; the validation done (L022, core 0.6.0; test gum); correlated inputs and the adaptive Monte Carlo: to do.
  • The dependency graph: a project of tables, formulas, fits and derived quantities; a change recomputes what depends on it, once, in order, and reports what changed (I04, R15) done (L020, core 0.4.0; test project on Hooke's whole practice); a model fit restarted from its last solution done (core 0.5.0).
  • The first practice's whole pipeline run from the command line, from its data sheet to its fit report.
Done when the first practice's (Ley de Hooke, L013) fits agree with SciPy to the printed digits and with KaleidaGraph's fit1 on the same data, from the command line. Met: SciPy for every fit (L016, L017, L021), KaleidaGraph's fit1 to every printed digit (L023). Phase 1 closes with core 0.6.0; KaleidaGraph's library files as definitions, correlated inputs and the adaptive Monte Carlo go to the core's later work.
PHASE 2 · open (L026)

The app: a fork of Code – OSS, as the TRAE IDE is, with Data, Plots, Fits and Formulas

The fork (L009): Code – OSS checked out, built, rebranded and stripped of what a laboratory tool does not need; then the first four modules as built-in contributions over a project folder, every number from the core, reached from the extension host. The umbrella of APP_CONVENTIONS.md (window, panels, menus, Settings, ⌘K, manuals) is the workbench's; what the checklist verifies is what we put in it.

  • The fork itself: Code – OSS at a pinned commit (1e81fc75, 1.143.0, checked out, built and launched as lab-plot-fit, L026–L027, app 0.1.0), the product's name done, icon and about box, the Mac build signed and notarised, the first build's time and size logged done (L027); the text workbench kept, the language services, debugger, terminal, SCM, chat and marketplace hidden (marketplace, chat, sign-in, welcome, onboarding, telemetry, updates, source control done (L028, app 0.2.0, patch 0001); the activity bar's Search, SCM, Debug and Extensions entries and the accounts item done (L029, app 0.3.0, patch 0002)); English and Spanish (L010).
  • The frame as ours: the activity bar's modules, the side bar's files by role done (L030, app 0.4.0), the inspector as the secondary side bar, the panel's formula console and logs, the status bar's items; projects in windows; versions through the workbench's timeline and local history.
  • The core reached: the command line as a process over stdio from the extension host (Q1), every call logged, no calculation in the window (the nophysics check carried over from diff-ref-struct). done (L027, app 0.1.0: lpf-core, "lpf 0.7.0" in the status bar); the nophysics check as a test: to do.
  • Data: the table with entry, import, sort, mask, statistics; the inspector for a column. entry, columns and rows, statistics, every change by the core (L030, app 0.4.0, core 0.8.0); import into the project, sort, mask, the inspector: to do.
  • Plots: the Gallery's types for version 1, the shared plot component (zoom, pan, crosshair, export), axes from the columns' units, error bars, residuals. scatter, line and lines, error bars, axes from the columns with ticks that never crowd, zoom, pan, crosshair, export, the plot following its table (L031, app 0.5.0, core 0.9.0); the fit line and the residuals with the Fits module; the Gallery's other types later.
  • Fits: a fit as a file, its report, refit on change; the general fit's definition with the library.
  • Formulas: the console, the history, the problems.
Done when the first practice can be done in the app from a blank project to the fitted plot, and the checklist of APP_CONVENTIONS.md is met for what is built.

On this page

    What this is

    The working site of one project: to build a Mac app with the features of KaleidaGraph and the window of the TRAE IDE, for the laboratory practices of the Physics degree, with a live bench mode where the student's readings become plots and fits as they are typed. It holds the brief, the study of KaleidaGraph, the design, the seed-place of ideas, a dated log of every step, the release notes and the manuals of the core and the app.
