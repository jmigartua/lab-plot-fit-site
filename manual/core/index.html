Using the core

Using the core: the lpf command line

Core 0.7.0. Every feature of the core is a command here; the app will call the same commands over stdio (Q1, L013). Every example on this page was run before it was published. The text of lpf help is this page's.

Build

cd core
cargo build --release          # target/release/lpf
cargo test --release           # every test, including the comparisons with SciPy and NumPy
lpf --version                  # lpf 0.7.0
lpf help [command]             # this manual, in the terminal

Data files

A table is a CSV whose header names each column with its unit in brackets, as the practices' files are written: M(g),x(mm),P(N),delta_x(m). The delimiter is found (comma, semicolon, tab); with a semicolon or a tab, a decimal comma is accepted. An empty field is an empty cell. A row with more fields than the header has names gets the extra fields as columns named c4, c5… by position, so that nothing measured is dropped. Any column can be addressed by its name or, as in KaleidaGraph, by its position: c0, c1…

lpf read data.csv              # the columns, their units, how many values and empty cells

Importing a file of unknown layout

lpf import scope_export.txt                                   # the guess and the table
lpf import datos.csv --decimal comma --header 2               # the user's corrections
lpf import datos.csv --save-as datos_std.csv                  # a copy in the app's standard format

The importer guesses how the data are organised and says so: the delimiter (tab, semicolon, comma or whitespace), the decimal separator (point or comma; a comma delimiter forces the point), the lines skipped (comments starting with #, %, // or !, blank lines, a preamble before the data), the header line and the units found in it (name(unit), name [unit]) or in a second line of units, each column's kind (numbers, text, empty), and whether the variables were laid out in rows and transposed. --delimiter, --decimal, --header (a line number, 0 for none) and --transposed override the guess. --save-as writes the table in the app's standard: name(unit) headers, commas between fields, the point as the decimal separator whatever the Mac's locale (R20).

Repeated readings

lpf stats data.csv --col t20 --resolution 0.01

The mean of the column's values, the course's "error cuadrático" (the error of the mean from the scatter), the sample standard deviation, and the error taken: the larger of the scatter and the instrument's resolution when one is given (theory).

Fits

The straight line y = m·x + n:

lpf fit data.csv --x delta_x --y P                 # m, n, Δm, Δn from the scatter; r, R², residuals
lpf fit data.csv --x delta_x --y P --origin        # through the origin
lpf fit data.csv --x M --y T2 --sigma 0.01         # weighted by σ (a value, or a column's name); errors from the weights
lpf fit data.csv --x M --y T2 --sigma dT2 --scaled # … scaled by √(χ²/dof)

A polynomial to order 9:

lpf fit data.csv --x V --y I --poly 2

The general fit of any equation in x, with named parameters and their starting values, bounds optional:

lpf fit data.csv --x t --y V --model "V0*exp(-x/tau)" --start V0=8,tau=10
lpf fit data.csv --x t --y V --model "V0*exp(-x/tau)" --start V0=8,tau=9 --bounds tau=0:10
lpf fit data.csv --x t --y V --model "a + b*x + c*x^2" --start a=0,b=1,c=0 --eps 1e-12 --max 500

Every result says where its errors come from: scatter (unweighted), weights, or weights scaled (theory). The general fit also reports the correlations, whether it converged and why it stopped, the parameters held at a bound, and the parameters the data cannot fix.

KaleidaGraph's standard fits, Exponential y = m0·e^(m1·x), Logarithmic y = m0 + m1·log(x), Power y = m0·x^m1, by linearisation as KaleidaGraph does them, or as the general fit of the same equation:

lpf fit data.csv --x t --y V --preset exponential                      # linearised: KaleidaGraph's standard fit
lpf fit data.csv --x t --y V --preset exponential --method nonlinear   # the true least squares, from the linearised start

The Linear fit's statistics as KaleidaGraph's View Results lists them, and the confidence bands:

lpf fit data.csv --x delta_x --y P --stats                 # adjusted R², standard errors, t, P, F, 95 % confidence limits
lpf fit data.csv --x delta_x --y P --stats --level 0.99
lpf fit data.csv --x delta_x --y P --band data             # the confidence band at every data x
lpf fit data.csv --x delta_x --y P --band 0,0.05,0.12 --prediction   # the prediction band at given x

Measurement uncertainty by the GUM

lpf gum "4*pi^2/a" --input a=2.369:gauss:0.077:11
lpf gum "M*g" --input M=0.030:res:0.001 --input g=9.80665:gauss:0.00001
lpf gum "(W1-W2)*tau/(M1-M2)" --input W1=typeA:52.1,52.3,52.0 --input W2=35.0:gauss:0.2 --input tau=360:res:1 --input M1=5.80:res:0.01 --input M2=3.95:res:0.01 --p 0.95 --mc 200000 --seed 1

Each input is name=value:kind:parameter: gauss:u[:dof] a Gaussian with its standard uncertainty (and degrees of freedom for a Type A given as u), rect:a a rectangular distribution of half-width a, res:δ the resolution of an instrument, tri:a a triangular one, or name=typeA:r1,r2,… the readings of a Type A evaluation. The report has three parts: the GUM uncertainty framework (the budget with each input's standard uncertainty, degrees of freedom, sensitivity coefficient, contribution and share; u_c, ν_eff, k, U and the coverage interval), the Monte Carlo propagation (M trials, the estimate, u, the symmetric and the shortest coverage intervals, the skewness) and the validation of the former against the latter at the tolerance of u written to --digits significant digits (theory).

Formulas on columns

lpf formula data.csv "T = t20/20" "T2[s^2] = T^2" --err t20=0.01
lpf formula data.csv "P[N] = M*g0" "tm = mean(t1,t2,t3,t4,t5)" "dt = sem(t1,t2,t3,t4,t5)" --out result.csv
lpf formula data.csv "E[cal] = W*tau" --upper      # the upper bound instead of quadrature

A formula is name = expression or name[unit] = expression. The expression names columns (or cN), the constants g0 (9.80665 m/\(\mathrm{s}^{2}\)), pi and e, and the functions below. It is evaluated row by row in SI; its unit is derived from the columns' units and checked (metres plus seconds is refused; a quantity's exponent must be a plain number; a function other than sqrt and abs wants no unit); the result is written in the unit asked for, or in the SI base form of its dimension. The uncertainty of each cell is propagated from the columns' uncertainties (set with --err, or carried from an earlier formula) and kept with the new column. --out writes the table with its new columns.

Expressions

lpf eval "4*pi^2/a" --with a=2.369474
lpf propagate "4*pi^2/a" --at a=2.369474 --errors a=0.076993 --upper
lpf propagate "b/a" --at a=2.369474,b=0.0543 --errors a=0.077,b=0.0084

The grammar: + − * / ^ with the usual precedence, ^ right-associative, unary minus below ^ (−x\(^{2}\) = −(x\(^{2}\))); parentheses; sqrt abs ln log exp sin cos tan asin acos atan sinh cosh tanh of one value; mean sem sd min max sum of several values in a row; pi, e. KaleidaGraph's fit definitions (a + b*x, a*exp(-x/b)) are written in the same arithmetic.

Units

Written as the guides write them: m/s^2, N/m, s^2, kg·m/s^2, cal, mV, kΩ, µs. The SI base and derived units (N, J, W, Pa, V, \(\Omega\), C, F, Hz, T, H), cal (4.186 J), eV, L, min, h, deg, %, with the SI prefixes. A value is converted between units of one dimension (Mkg[kg] = M with M in g; E[cal] = W*tau); a conversion between dimensions is an error.

Projects

lpf project hooke.json graph                      # the nodes and what each depends on
lpf project hooke.json run --save                 # everything recomputed in order; the results saved in the file
lpf project hooke.json set "dynamic.t20[0]=7.45" --save    # one cell changed: only what depends on it is recomputed

A project is a JSON file: tables (named tables with their columns, units and uncertainty rules), formulas (each {"table", "text"}, the text as in lpf formula), fits (each with a name, its table, x and y columns, a kind of line with origin, poly with order, or model with equation, parameters, start and bounds; sigma a column's name, "auto" for the y column's own uncertainties, or empty), and derived (each with a name, an expression over the fits' parameters written fitname_param, such as 4*pi^2/dynamic_m, and other derived names; upper_bound for the course's rule; a unit for the report). run computes every node in dependency order and writes fit_results and derived_results into the file with --save. set changes cells (an empty value clears; a row past the end extends the table) and recomputes only what depends on them, printing the list of what changed with each node's outcome, which is what the Bench shows on each reading. A node that fails (a formula whose units do not match) reports its message; the rest runs. A cycle, or a dependency on a column that does not exist, is refused with its name.

Output

Every command writes JSON to standard output, with the same fields the library returns (LineFit, PolyFit, NonlinearFit, Repeats, Propagated, Applied); an error goes to standard error with exit code 2 and says what was wrong and what to do.
