Using the app

Using the app

App 0.8.0 with core 0.12.0. One section per module as each is built; the text of each section is what the module's help shows. Numbers are written and shown with the point as the decimal separator; a comma typed on entry is accepted and written as a point (R20).

Installing the app

The app is a Mac application, lab-plot-fit.app, built from this repository (app/tools/package_mac.py, app 0.8.0): drag it to Applications and open it. It is signed for the Mac it was built on; on another Mac, macOS asks once: right-click the app, Open, and confirm. On the first launch macOS also asks for the login keychain ("lab-plot-fit wants to use your confidential information stored in lab-plot-fit Safe Storage"): that is the app's own encrypted store, where a GitHub sign-in would live; Always Allow is safe, and the window waits until the dialog is answered. Notarisation, which would make that step unnecessary, needs an Apple Developer account. A project folder dragged onto the app's icon in the Dock opens as the project; a table or a plot file dragged onto it opens in its module (the first time a kind of file is opened the app may show it as text: close it and open it again from the Project view).

The window

The app is a fork of Code – OSS, as the TRAE IDE is: the window is the workbench with a laboratory tool's things in it, and the workbench's own infrastructure kept where it may serve later. On the left, the activity bar: the Explorer (the folder as it is on disk), Search, Source Control (git, and GitHub through it), Extensions (the Open VSX registry), the Project view (the files by role, below), and at the bottom Manage (settings, keyboard shortcuts). The AI chat, the welcome tour, telemetry and updates are off. The main area holds the tables and, later, the plots, fits and report pages as tabs; a table and its plot side by side is the normal arrangement. The status bar shows the core's version (lpf 0.8.0); clicking it opens the log of every call the window made to the core.

A project is a folder: File ▸ Open Folder…, or a folder given when the app starts. Every file of a project is readable text, so that a student can open any of it without the app.

The project's files by role

The Project view does not list the folder alphabetically. It shows what each file is for the practice, in groups: Practice (the template, *.practice.yml), Data (the tables: .csv, .tsv, .dat, .txt), Imported originals (Data/originals/, untouched), Plots, Fits, Layouts, Report, Bench sessions, Versions (closed by default) and Other files. A file's role comes from its folder or its name. Hovering a table says its size and its columns with their units. The buttons in the view's title: a new table, the folder as it is on disk (the Explorer), refresh.

Data: the table

A table is a CSV file whose header names each column with its unit in brackets, M(g),x(mm),P(N): the practices' own format, the core's standard. Opening one shows it as a grid: the column's name and unit in its header, the rows numbered from 0 as KaleidaGraph numbers them, and below the last row the next reading row, always there, where the next value goes. The cells are shown exactly as the file writes them: 0.10 stays 0.10.

Entering values. Click a cell and type; Return commits and moves down, Tab moves right, Escape cancels; the arrows move the selection; Return or F2 on a selected cell edits it; Delete empties it. A comma typed as the decimal separator is accepted and written as a point; a value that is not a number is refused with a message above the grid, and nothing is written. Typing into the next reading row adds the row. Shift with a click or the arrows selects a range; ⌘C copies it as tab-separated text with the header, which pastes into a spreadsheet; clicking a column's header selects the column.

Rows and columns. The toolbar above the grid, the editor's title buttons and the palette: Sort ↑ and Sort ↓ order the rows by the selected column (click its header), empty cells last, the other columns following their rows; Add a row (⌘↩) adds an empty row at the end; Add a column… (⌘⇧↩) asks the name and the unit; Rename the column… (or double-click its header) changes the name and the unit; Delete the column and Delete the row ask for confirmation when values would go. Show column statistics adds a footer with each column's n, mean, error of the mean (s/√n, the course's error cuadrático) and sample standard deviation, from the core. Open as text shows the same file in the text editor; both views follow each other.

What the app does with the file. The file's text is the truth: every change is sent to the core (lpf edit, the core's manual) with the document's text, and the CSV that comes back replaces the document. So the workbench's undo (⌘Z) takes a table back change by change, auto-save writes the file after a pause, the Timeline keeps local history, and a file changed outside the app is noticed. The window never writes a number itself.

Importing a file. The Project view's import button (or Data: Import a data file into the project…): any text file of data, a KaleidaGraph export, a spreadsheet's CSV with commas as decimals, an instrument's dump with a preamble. The core guesses how it is organised and the guess is shown as one line (the delimiter, the decimal separator, the header line, whether the variables were laid out in rows, the rows and the columns found); each part can be changed, and the guess runs again. Importing writes a copy in the app's standard format beside the project's tables and keeps the original, untouched, in originals/ (the Imported originals group); the table opens.

A new table. The Project view's first button, or Data: New table in the palette: a file name, then an empty grid; add a column to begin.

Plots

A plot is a file of the project, name.plot.json, that names its table and columns and holds no copy of the data: a plot always follows its table. Change a value in the table and the plot moves; there is no Update Plot.

Making one. On a table, the New plot from this table… button of the editor's title (or the palette): the x column, the y columns (one or more), the column of y's uncertainty for error bars, or none. The file is written beside the table, named after it and its y columns, and opens beside the table. A plot file in the Project view's Plots group opens the same way.

The controls above the plot edit the file, so ⌘Z takes them back: x, y, error bars, the kind (points; points and lines; lines), log x, log y, the title. The axes are labelled from the columns' names and units; a typed label in the file overrides. Ticks never crowd: as many as the width allows, in steps of 1, 2 or 5; when the numbers are long their common factor (\(\times 10^{-5}\)) or their offset (+ 10.6048) goes into the axis title so that each tick shows only the digits that change.

The band. When the plot lists a straight-line fit, the band control draws its confidence band (where the true line lies, at the fit's confidence level) or its prediction band (where a new reading would fall), shaded under the line, with the level in the fit's label; theory.

Looking closer. Drag a box to zoom to it; the wheel zooms at the cursor; ⌥-drag pans; double-click, or Reset the view, shows everything again. The readout at the top right gives the values under the cursor. The view is not saved in the file: a fixed range in the file (xrange, yrange) is.

Out of the app. Export as SVG… and Export as PNG… (at twice the screen's size) save the plot as drawn; Copy as SVG (⌘C) puts it on the clipboard for a document that takes SVG. Open as text shows the file itself. The figure rules of the family (identical geometry across a series, LaTeX text) are the Report module's, later.

Fits

A fit is a file of the project, name.fit.json, naming its table, its columns and its model; it holds no result that the core cannot recompute, and it is refit whenever its table changes. A fit on a plot is drawn over the data with its parameters as a label, and its residuals in a panel below, on an axis of their own.

Making one. On a plot, New fit… (the editor's title, the + fit button of the plot's toolbar, or the palette): the kind, then the weights. On a table, the x and y columns first. The kinds: the straight line y = m·x + n, the line through the origin, a polynomial (its order), KaleidaGraph's exponential, logarithmic and power fits, and the general fit of any equation in x with named parameters and their starting values (V0*exp(-x/tau), V0=8, tau=10). The weights: none, a column of y's uncertainty, or one uncertainty for every point. The file is written beside the table, added to the plot it was made on (the plot shows its fits as chips; × takes one off the plot and keeps the file), and its report opens beside.

The report. The equation with the columns' names; each parameter written as the lab report needs it, m = 16.2 ± 0.2 N/m, by the course's rule (one significant figure in the error, two when it starts with 1, the value to the error's last place) and with its unit from the columns' units; the points, the degrees of freedom, \(\chi^2\), \(\chi^2\)/ν, R\(^{2}\) and r, where the errors come from (the scatter, the weights, the weights scaled) and whether the fit converged; for a straight line, the statistics KaleidaGraph's View Results lists (adjusted R\(^{2}\), the standard error of the estimate, t and P, F, the confidence limits at the level chosen); the residuals row by row; and the report's lines, which Copy the report (⌘C) puts on the clipboard.

The controls above the report edit the file, so ⌘Z takes them back: the kind, through the origin, the order, the model and its starting values, the weights, scaled by √(\(\chi^2\)/ν), the method (linearised as KaleidaGraph does the three standard fits, or nonlinear), the confidence level. Open as text shows the file itself.

Formulas

KaleidaGraph's Formula Entry is a console in the panel at the bottom of the window: the button on a table's title, Formulas: show the console (⌘⌥F), or the Formulas tab of the panel. The line above the console names the table in front and its columns.

A formula is name[unit] = expression: P[N] = M*g0, T = t20/20, T2[s^2] = T^2, v[m/s] = x/t. Columns by name or by position (c0, c1…); the constants g0, pi, e; the functions sqrt abs ln log exp sin cos tan asin acos atan sinh cosh tanh, and mean sem sd min max sum over several values of a row (mean(t1, t2, t3)). The unit is derived from the columns' units and checked: metres plus seconds is refused with the reason; the unit in brackets is the one asked for (P[N] from grams and g0), else the SI base form. Return, or Apply, adds the column to the table (or replaces a column of that name); ⌘Z takes it back.

Uncertainties. Give the columns' uncertainties on the line below, M=0.1, t20=0.01 (the instruments' resolutions, in the columns' units); the new column then gets its uncertainty propagated cell by cell, by quadrature or, with the switch, by the upper bound, written as a column delta_name beside it. The line is remembered with the project.

The history keeps the formulas applied in the project; a click puts one back on the line. A problem (a column that does not exist, a unit that does not match) is said under the line, and nothing is written.

On this page

    What this is

    The working site of one project: to build a Mac app with the features of KaleidaGraph and the window of the TRAE IDE, for the laboratory practices of the Physics degree, with a live bench mode where the student's readings become plots and fits as they are typed. It holds the brief, the study of KaleidaGraph, the design, the seed-place of ideas, a dated log of every step, the release notes and the manuals of the core and the app.
